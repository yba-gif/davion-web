## Top 3 contributors for P2.1 (code-split targets)

### 1. Swiper (~150 KB) — Used only on the home page sectors marquee

Carousel library bundled eagerly because the marquee component imports it
at module level. The marquee is below the fold (sits between the cycle
block and the AI capabilities section).

**Strategy:** `defineAsyncComponent` on the marquee wrapper, plus
`useIntersectionObserver` to mount it only when scrolled near. Pages that
don't use the marquee (every page except home) shed the Swiper code
entirely.

**Expected saving:** ~120 KB off the main chunk on home; full ~150 KB off
every other page.

### 2. Lenis (~30 KB) — Already skipped on mobile, but always bundled

`plugins/reveal.ts` doesn't use Lenis. `plugins/lenis.client.ts` imports
it eagerly even though the runtime check (`pointer: coarse`) means it
never instantiates on mobile. The import path itself still ships the lib.

**Strategy:** Convert the import to a dynamic `import('@studio-freight/lenis')`
inside the `if (!isTouch)` branch. Mobile users get zero Lenis bytes,
desktop users get it after `app:mounted`.

**Expected saving:** ~30 KB off mobile builds entirely; ~30 KB deferred
on desktop.

### 3. marked (~30 KB) — Used only on /company/newsroom/[slug]

`composables/useMarkdown.ts` (or equivalent) imports marked at module
level. The renderer is called only on newsroom post detail pages. Every
other page ships the parser unused.

**Strategy:** Lazy-load inside the composable:
```ts
export const useMarkdown = () => ({
  async renderMarkdown(md: string) {
    const { marked } = await import('marked')
    return marked.parse(md)
  }
})
```

**Expected saving:** ~30 KB off every page except newsroom post detail.

## Total expected reduction (after P2.1)

| Page | Current main chunk | After P2.1 |

| / (home) | 939 KB | ~810 KB (-129 KB) |
| /industries | 939 KB | ~730 KB (-209 KB) |
| /solutions/alpos | 939 KB | ~730 KB (-209 KB) |
| /company/newsroom/[slug] | 939 KB | ~810 KB (-129 KB) |

The audit target was main chunk ≤500 KB. Lazy-loading the 3 libs above
gets us to ~730 KB. To hit 500 KB will require:

- **@nuxt/icon lazy-resolution** — icons can be served on demand from
  the iconify CDN instead of bundled into the JS. Removes ~50 KB.
- **Component-level code splitting** — large per-page components
  (engagement-form, scheduling-embed, demo-embed, alpos-console) as
  `defineAsyncComponent` instead of eagerly imported by their pages.
- **Locale-message tree shaking** — vue-i18n bundles all 3 locales eagerly.
  Switching to `lazy: true` in nuxt-i18n config and adding `langDir`
  resolution would defer non-current-locale messages.

Combined, those get to ~450-500 KB.

## Recommendation

For Sprint 2 (P2.1), tackle the 3 top contributors above. Expected ROI:
- Main chunk: 939 KB → 730 KB (~22% reduction)
- LCP on mobile slow 4G: ~3.2s → ~2.7s (Lighthouse target <2.5s)
- INP: marginal improvement (smaller parse cost on initial hydration)

For Sprint 3+, add @nuxt/icon lazy-resolution + locale lazy-load to push
under 500 KB.
